# STHGroup

### Интерфейс 2.1 — «Центр заказа»

Утверждённый стиль Liquid Glass применяется к оболочке, навигации, кнопкам, формам, диалогам и базе материалов; таблицы имеют плотную подложку для читаемости. Тема продолжает отвечать за цвета. В заказе — крупный заголовок, реальные этапы книги, блоки изделий, расчёта и оплат, независимый итог справа. Реквизиты находятся в «Данные заказа», скидки и условия раскрываются справа. «Все заказы» возвращает доску; переключатель «Список» сохраняет поиск и прежний список заказов. Раскрытие блоков, прокрутка и фокус полей сохраняются при пересчёте формы. На узком окне итог переносится под содержимое. PDF использует прежние шаблоны.

Проверка интерфейса: установить Playwright отдельно и запустить `node test/fixtures.js`, затем `node test/t_glass_ui.js` (по умолчанию — отдельный headless Edge). Если пакет находится вне проекта, `STH_PLAYWRIGHT` задаёт путь к нему. Тест создаёт только временные демонстрационные данные; проверяет реквизиты, оплаты, неизменность стоимости, этапы, изделия, доску/список, смету, ошибки JavaScript и размеры окна; сохраняет снимки.

### Проверка перед КП

В карточке заказа нажмите «Проверить заказ». Такая же проверка выполняется перед «КП в PDF»: цены и сопоставление материалов, отсутствующий или устаревший раскрой, неразмещённые детали и расхождение с сохранённым расчётом изделия. Проверяются все изделия: открытые вкладки — в памяти, остальные — из файлов. Из замечания кнопка «Открыть» ведёт к позиции сметы, раскрою или вкладке «Изделия». Проверка не исправляет данные автоматически. Можно вернуться к исправлениям или явно открыть КП с предупреждениями. Без замечаний КП открывается сразу.

### Колонки заказов

«+ Колонка» добавляет этап в конец доски. Перетащите любую колонку за заголовок: линия показывает место вставки. С клавиатуры — фокус на заголовке и Alt + стрелка влево/вправо. Порядок записывается в книгу заказов и восстанавливается после перезапуска; статусы заказов сохраняются. Щелчок по заголовку по-прежнему переименовывает этап.

### Карточка материала в смете

Нажмите название позиции: её свойства откроются справа, а строка подсветится в таблице. Цена и количество доступны и в таблице, и в карточке; после изменения пересчитываются сумма строки и итог сметы. В карточке сохранены артикул, режим расчёта, сведения модели, поставщик и выбор материала базы. Закрыть карточку можно крестиком или повторным нажатием названия. При фильтрации показывается карточка видимой позиции.

Для проверки: откройте модель, перейдите в «Смета», выберите несколько материалов по очереди, измените цену справа и сравните сумму с таблицей. Проверьте фильтры, закрытие карточки, сопоставление с базой и строку с заменённым материалом (поля из базы остаются только для чтения).

Программа для Windows к «БАЗИС-Мебельщику» для производства STHGroup: модель в 3D, раскрой листов, смета, база материалов. С версии 0.7.0 окно программы — копия окна BazisReborn (папка `web`), без разделов «Деталировка», «Присадка», «Сборка», без отзывов, регистрации и обновлений BazisReborn.

## Устройство
- `main.js` — оболочка Electron: окно, системные окна выбора файла, PDF (печать встроенным Chromium), открыть файл/ссылку, масштаб, вход на сайты магазинов (`/api/shop/login`, `/api/shop/fetch`), обновления через GitHub Releases (electron-updater) — как раньше. Принудительная проверка — кнопка «Проверить обновления» в настройках (вкладка «Обновления»): окно зовёт `POST /api/upd/check`, сервер передаёт вызов оболочке (`hooks.updCheck`), та спрашивает GitHub, сама качает новую версию и предлагает перезапуститься.
- `server.js` — локальный сервер для окна: те же адреса `/api/*` и токен `X-BM-Token`, что у программы BazisReborn (`app/go/server.go`), в том числе проект одним файлом (zip без сжатия внутри `.bmk`). Ядро C++ BazisReborn не подключено — считает JS.
- `web/` — окно и расчётное ядро (копия `app/web` BazisReborn 2.2.1). Правки STHGroup помечены комментарием «STHGroup».
- `bazis/STHGroup_Export.js` — скрипт выгрузки модели из БАЗИСа в проект `.bmk` (на основе скрипта BazisReborn 1.11). Окно выгрузки (mshta, вариант «C»): слева сводка модели и ход выгрузки, справа данные заказа — заказчик, номер заказа, изделие, комментарий (в проект: `model.customer`, `model.orderNo`, `model.title`, `model.note`). Закрыли окно — выгрузка отменена; нет mshta — данные из модели, программа открывается сама. Ставится из программы: «Файл → Скрипт для БАЗИСа…» (папка STHGroup в папке скриптов БАЗИСа, скрипт латиницей + значок `STHGroup_Export.bmp`); при каждом запуске программа обновляет его и пишет свой путь в `%APPDATA%\STHGroup Cutting\exe.txt`.
- Тема выбирается в настройках: исходная «STHGroup» и три темы 2.0 — «Светлая мастерская», «Северный синий», «Графит» (`web/core/sth_themes.js`, `web/sth_v2.css`). Там же настраивается плотность интерфейса. Заставка BazisReborn отключена; своя — `web/ui/sth_splash.js` (вариант «Спокойная»: знак с тёплым свечением, буквы названия по очереди, версия программы; ~2 с, щелчок или клавиша — пропустить; не показывается при выключенных анимациях).
- База материалов — окно BazisReborn (`web/matbase.html`). STHGroup добавляет (`web/ui/sth_shop.js`, разбор страницы — `web/core/linkparse.js`): в карточке на вкладке «Поставщик» у «Ссылки на товар» — «Заполнить по ссылке» (цена, наличие, артикул, название, размеры, поставщик, остаток и характеристики в примечание) и «Войти на сайт»; «Инструменты → Обновить цены по ссылкам…». Групповое редактирование (`web/ui/sth_mb.js`) — как в БАЗИСе: та же карточка «Материал» с пустыми полями, меняется только заполненное, галочки в три положения, классы «Добавлять / Заменить»; Ctrl+A — выделить все.
- «Нет в базе» (`web/ui/sth.js`): после открытия проекта — плиты, кромка, погонные, фурнитура и профили сметы, которых нет в базе, списком с галочками; правятся название и артикул, группа — своя для вида (или новая «Из моделей: …»); записываются с единицей, толщиной и форматом листа из проекта. Окно — один раз на набор недостающего, снова — кнопкой «Нет в базе: N» над сметой.
- «Материал из базы…» (`web/ui/sth_replace.js`, с 2.0.0): одна кнопка у строки сметы (плита, кромка, погонный, фурнитура, профиль) объединяет сопоставление и замену; режим выбирается внутри окна. Сопоставление связывает наименование модели с материалом базы для цены и остатков; замена подменяет название, артикул, количество/единицу, цену, поставщика и фото в смете, документах и заказе. Общие правила действуют во всех проектах, исходное название модели остаётся в подсказке заменённой строки, замену можно вернуть.
- Смета 2.0 (`web/core/sth_est.js`, `web/ui/sth_est.js`): компактная основная строка у каждой позиции; стрелка раскрывает вниз прежние поля и действия (артикул, наименование, поставщик, режим расчёта, данные модели и материал базы), повторный щелчок сворачивает. Сохранены массовые действия, фильтры «все / проблемные / заменённые / без цены / со склада» и перетаскивание столбцов.
- Окно «Поставщик» у строки сметы (`web/ui/sth_sup.js`): материал базы строки («✓», «Сопоставить…» или «Записать в базу»), ссылка с «Заполнить по ссылке» и «Войти на сайт», цена, поставщик, артикул, фото — всё пишется в базу материалов; над сметой — «Обновить цены по ссылкам» (фото с сайта — `/api/shop/image` в `main.js`).
- Заказы и клиенты (`web/core/sth_order.js` — книга и расчёт, `web/ui/sth_orders.js` — разделы, справочник, КП и счёт): разделы «Заказы» (список | заказ: Расчёт / Изделия / Оплаты | итог, аванс, условия) и «Клиенты». Книга — файл «STHGroup — заказы.json» в общей папке (по умолчанию — папка базы материалов). Заказ — несколько изделий (.bmk); открытый проект сам попадает в заказ по номеру из окна выгрузки или по файлу, иначе — новый заказ с клиентом из окна. Расчёт как у фабрики: обработка листового материала за лист по виду работы (вид — по словам в названии материала), мелкие детали (длина или ширина меньше порога: кромление, присадка — за деталь), услуги с галочками (за заказ, лист, изделие, деталь, % от суммы), скидка за комплекс (% от услуг), материалы и фурнитура по смете с наценкой, аванс (% услуг + % материалов), доплата, оплаты, долг. Модель изделия копируется в папку заказа («Заказы\\<номер клиент>» в папке заказов), щелчок по заказу открывает его модели. Вид работы за лист — по словам в названии материала и толщине; разделы «Дополнительные работы», «Фасады МДФ с эмалью», «Фрезеровка без эмали» — количество вписывается в заказе; «Срочно» — +30% к услугам. Работы (распил, кромка, пазы и др.) в смете не показываются — они в заказе. КП (макет «B») и счёт — предпросмотр в окне программы, затем PDF. «Своя строка» в услугах — название, единица, цена, количество правятся в строке.
- Карточки заказов и CRM 2.0 (`web/ui/sth_kanban.js`, `sth_crm.js`, `web/ui/sth_crm.js`): доска с шестью этапами и перетаскиванием; подключение CRM из настроек, проверка соединения, ручной и автоматический приём заявок, создание карточек без дублей. Логин и пароль вводятся только в программе; пароль и cookie-сессия хранятся локально в зашифрованном виде через Electron `safeStorage`.
- «Сегодня» и состояние (`web/core/sth_workspace.js`, `web/ui/sth_workspace.js`): стартовая сводка заказов, долга и CRM, быстрые действия, центр уведомлений, постоянная строка состояния проекта и общий прогресс долгих операций.
- Склад и копии 2.0 (`web/core/sth_stock.js`, `web/ui/sth_stock.js`, `sth_backup.js`): история замен и складских действий, импорт остатков, понятные пустые состояния; при переходе «В работе» остатки проверяются до подтверждения списания. База материалов автоматически копируется каждые 30 минут в `.sth-backups` рядом с базой, хранятся до 12 последних копий.
- Простой раскрой 2.0 (`web/core/sth_cut_simple.js`, `web/ui/sth_cut_simple.js`): основной экран показывает количество листов, деталей и неразмещённых позиций; прежняя карта и технические инструменты сохранены в «Подробнее».

Полное описание для продолжения работы — `ПОЛНОЕ ОПИСАНИЕ.md`, правила работы с автором — `AGENTS.md`, картинки выбранных вариантов оформления — `docs/design/`.

## Проверки
```bash
npm test          # заказы и расчёт КП (t_orders), образцы моделей, выгрузка с окном данных заказа (t_export), моделей (имитация БАЗИСа), раскрой, проект, смета, база материалов, замена позиций (t_replace), проект одним файлом, сервер окна, заставка (t_splash)
node server.js <папка данных> [проект.bmk] [порт]   # окно без Electron — для проверок в Chromium (Playwright)
```
`t_est.js` нужны `pdfinfo`, `pdftotext`, `unzip` — на сборке GitHub (Windows) идёт `npm run test:ci` без него.

## Выпуск
Поднять `version` в `package.json` и отправить в `main`: GitHub Actions соберёт установщик и выпустит его, установленные программы обновятся сами.
