# STHGroup — полное описание проекта (для человека и для нейросети)

Состояние на 06.11.2026, версия **2.3.2**. Этот файл — точка входа: что это, как устроено, где данные, как проверять и выпускать, какие решения приняты автором и почему, что не проверено и что не закончено. Правила работы с автором — в `AGENTS.md` (обязательно прочитать).

Репозиторий: **https://github.com/MatrixMind2026/sthgroup-cutting** (открытый, ветка `main`). Выпуски и автообновление — там же (GitHub Releases).

---

## 1. Что это и зачем

**STHGroup** — программа для Windows для мебельного производства **STHGroup** (свои станки: Nesting, сверлильно-присадочный с ЧПУ, кромочный с прифуговкой). Задача — по модели из **БАЗИС-Мебельщика** посчитать заказчику работу и материалы (коммерческий распил), вести заказы, клиентов, оплаты, выпускать КП и счёт.

Рабочее название в установщике и папке данных — **«STHGroup Cutting»** (окончательное название программы автор выберет позже). В окне программы — «STHGroup».

**С версии 0.7.0 программа полностью переделана**: окно и расчётное ядро — копия окна программы автора **BazisReborn 2.2.1** (раскрой, 3D, смета, база материалов), поверх добавлено своё STHGroup (заказы, клиенты, расчёт «как у фабрики», КП/счёт, ссылки на товар, «Нет в базе», «Сопоставить с базой», свой скрипт выгрузки, тема). Прежняя программа (0.1–0.6.1, своё окно и свой разбор .b3d) удалена — автор признал её неудобной и с неправильным расчётом. Начали «с чистого листа»: старые заказы и база не переносятся.

Кто пользуется: автор (Глезерис Евгений Алексеевич) на своём производстве; данные можно держать в общей папке (Яндекс Диск) на нескольких компьютерах.

## 2. Как устроено (в трёх словах: Electron + локальный сервер + окно BazisReborn)

BazisReborn у автора — программа на Go (локальный HTTP-сервер + окно WebView2) с окном на HTML/JS. Для STHGroup Go-часть **не используется**: её заменяет оболочка **Electron** с сервером на Node.js, который отвечает окну **по тем же адресам `/api/*` и с тем же токеном `X-BM-Token`**, что Go-сервер BazisReborn (`app/go/server.go`). Поэтому окно BazisReborn работает почти без правок. Так сделано по решению автора: **обновления должны остаться как были** (electron-updater + GitHub Releases), установленные STH обновились сами с 0.6.1 на 0.7.x.

```
main.js      оболочка Electron: окно, системные окна, PDF, масштаб, вход на сайты магазинов, автообновление
server.js    локальный сервер для окна (127.0.0.1, случайный порт, токен) — повторяет app/go/server.go
web/         окно и ядро — копия app/web BazisReborn 2.2.1 + файлы и правки STHGroup
bazis/       скрипт выгрузки из БАЗИСа STHGroup_Export.js + значок STHGroup_Export.bmp (48×48)
assets/      значок и логотипы STHGroup (svg/png/ico)
test/        проверки (Node.js) и имитация БАЗИСа
.github/workflows/build.yml   сборка установщика и выпуск на GitHub при push в main
```

### 2.1. `main.js` (Electron)
- Один экземпляр (`requestSingleInstanceLock`); файл `.bmk` из командной строки → `boot.file`; второй запуск с файлом → `srv.activate(path)` (окно подхватит через `/api/ping` → `reload`).
- `hooks` для сервера: `dialog` (системные окна open/save/folder), `pdf` (HTML → временный файл → скрытое окно → `printToPDF`), `open` (shell.openPath), `openUrl`, `zoom` (setZoomFactor), `title`, `quit`, `toFront`.
- `window.open` своих страниц разрешён (окно «База материалов» — `matbase.html`), чужие ссылки — во внешний браузер.
- **Вход на сайты магазинов**: профиль `persist:shops`. `/api/shop/login` — окно сайта (логин/пароль вводит человек на сайте, программа их не видит), `/api/shop/fetch` — страница в скрытом окне под этим входом (ждёт 2,5 с скриптов), возвращает HTML.
- При запуске (только установленная версия): пишет свой путь в `%APPDATA%\STHGroup Cutting\exe.txt` (для скрипта выгрузки) и, если в настройках есть `sthScripts`, переустанавливает скрипт в папку скриптов БАЗИСа (скрипт обновляется вместе с программой).
- Автообновление: `electron-updater`, проверка при запуске (выключается галкой «проверять обновления при запуске» в настройках), скачивание в фоне, вопрос «Перезапустить сейчас / Позже». Принудительная проверка — кнопка «Проверить обновления» в настройках, вкладка «Обновления» (раздел «Общие»): окно зовёт `POST /api/upd/check`, сервер передаёт вызов оболочке (`hooks.updCheck`, main.js), та спрашивает GitHub и отвечает окну (`none` / `available` / `error` / `dev` / `checking`); новая версия качается сама (`autoDownload`), по готовности — то же окно «Перезапустить сейчас / Позже». Состояние (версия, когда проверяли, последняя, ошибка) оболочка отдаёт через `hooks.updState` → `GET /api/upd/state`.
- Папка данных — `app.getPath('userData')` = `%APPDATA%\STHGroup Cutting`.

### 2.2. `server.js`
Адреса (все с токеном): `GET /api/boot` (edition `'sth'`, `core:false`), `GET/PUT /api/settings`, `GET/PUT /api/file` (в т.ч. «проект одним файлом» — zip без сжатия внутри .bmk, путь `файл.bmk!внутренний/путь`, `from=` для «Сохранить как» с 3D), `GET /api/stat`, `GET /api/ls`, `GET /api/tree`, `POST /api/mkdir`, `POST /api/dialog`, `POST /api/pdf`, `POST /api/open`, `POST /api/openurl`, `GET /api/md5`, `POST /api/zoom|title|ping|bye|current|activate|quit`.
Заглушки (окну говорим «нет/не нужно»): `/api/core` (503 — ядро C++ не подключено, окно считает на JS), `/api/tester/*`, `/api/feedback/state`, `/api/reg/state`, `/api/sound/*`. Обновления (`/api/upd/state`, `/api/upd/check`) — через hooks оболочки; без неё (тесты, браузер) — как раньше заглушка `{status:'skip'}`.
Своё STHGroup: `POST /api/sth/script` — положить скрипт выгрузки в папку скриптов БАЗИСа (`installScript`: папка `STHGroup` внутри выбранной; скрипт переводится в латиницу — каждый не-ASCII знак → `\uXXXX`, как `tools/ascii_script.py` у BazisReborn, потому что БАЗИС может читать скрипт как Windows-1251; путь к программе вписывается вместо `'%%BM_EXE%%'`). С 2.0.0 оболочка добавляет `POST /api/sth/materials-backup` (резервная копия базы) и `/api/sth/crm/state|connect|test|sync|disconnect` (подключение и приём заявок CRM).
Запуск без Electron для проверок: `node server.js <папка данных> [проект.bmk] [порт]` (есть подставной магазин: `STH_SHOP_HTML=<файл>`, подставное окно выбора: `STH_DIALOG=<путь>`). Маршруты резервных копий и CRM подключаются оболочкой Electron, поэтому в автономном `server.js` их нет.
Тема ставится в странице сразу; пользовательские темы 2.0 используют `data-theme="light|dark"` и `data-skin="sth-workshop|sth-nordic|sth-graphite"`.

### 2.3. `web/` — окно (копия BazisReborn 2.2.1)
Без сборщика, порядок `<script>` в `index.html` важен. Глобальные объекты BazisReborn: `BM` (ядро: `BM.project`, `BM.cut`, `BM.est`, `BM.mb`…), `UI` (`UI.api`, `UI.modal`, `UI.pick`, `UI.toast`), `App` (`App.S` — состояние), разделы `Est`, `MatBase`, `Model`… Подробности по ядру BazisReborn — в его документации (`docs/handoff/` в папке BazisReborn у автора; здесь её нет).

## 3. Разделы программы (что видит человек)

Полоса слева: **Сегодня, Заказы, Склад, Модель, Раскрой, Смета, База, Клиенты**.

- **Сегодня** — стартовый экран: активные заказы, производство, готовность, долг, принято из CRM, заказы, требующие внимания, быстрые действия и последние уведомления.
- **Модель** — 3D BazisReborn (виды, рентген, фасады, анимация, свет, «Заказчику»…).
- **Раскрой** — основной экран «Листы в заказе»: количество листов, деталей и неразмещённых позиций по материалам, пересчёт конкретного материала. «Подробнее» открывает прежний гильотинный раскрой BazisReborn (ФРС, Nesting), правки, остатки, «Улучшить», PDF/Excel/DXF/CSV.
- **Смета** — смета BazisReborn (прайсы, разделы, правки строк, документы), массовые действия и фильтры «все / проблемные / заменённые / без цены / со склада». У каждой строки материала — **«Материал из базы…»**: сопоставление или замена выбираются внутри окна; у заменённой строки видна подсказка с исходным названием модели.
- **База** — окно «База материалов» BazisReborn (группы, карточки как в БАЗИСе, классы, поставщики, склад, импорт/экспорт CSV/DBF/XML) + ссылка на товар. Автоматические копии — каждые 30 минут, до 12 последних.
- **Склад** — листы, обрезки, кромка/погонаж, фурнитура и движения; приход, расход, резерв, импорт остатков, история действий. При переводе заказа «В работе» сначала показывается проверка остатков; списание выполняется только после подтверждения.
- **Заказы** — прежний список/заказ и доска карточек с шестью этапами: Расчёт → Согласован → В работе → Готов → Отгружен → Закрыт. Карточку можно перетащить; история переходов сохраняется. В заказе — номер, клиент, дата, статус, комментарий, вкладки «Расчёт», «Изделия», «Оплаты», итог, скидка, аванс/доплата/оплачено/долг, условия, «КП в PDF», «Счёт в PDF», «Справочник и цены…».
- **Клиенты** — список, карточка (имя, телефон, почта, примечание), заказы клиента с суммами и долгом, «+ Заказ для клиента».

## 4. Логика STHGroup подробно

### 4.1. «Нет в базе» (`ui/sth.js`)
После открытия проекта (обёртка `App.openPath`, через 1,2 с): строки сметы видов panel, linear, edge, fastener, profile, для которых `MatBase.rowInfo(w)` пусто. Окно: галочка, вид, наименование и артикул (правятся), ед. и размер, группа базы (группы нужного типа или «＋ новая «Из моделей: листовые/кромка/фурнитура/прочее»»). «Записать в базу» — материалы создаются (`MB.defMat` + единица, для плит толщина, формат листа из настроек раскроя, текстура). Показывается один раз на набор недостающего (`settings.sthMiss[путь] = подпись`), снова — кнопкой «Нет в базе: N» (счётчик — по последней смете `Est.R`).
Типы: panel/linear → группа `sheet` (kind `sheet`/`lin`), edge → `edge`, fastener → `fit`, profile → `other`.

### 4.2. «Сопоставить с базой» (`ui/sth.js`)
Связь «наименование строки модели → материал базы» хранится **в файле базы** (`b.links`, ключ `вид|наименование в нижнем регистре`, несколько вариантов имени строки: `name0`, `skey`, `title`). `MatBase.rowInfo` переопределён: сначала связь, потом обычный поиск BazisReborn (`MB.infoFor` по наименованию/артикулу). Окно выбора: поиск (слова из названия, артикул даёт +100), фильтр «только <тип группы>», двойной щелчок, «Отвязать». После — `MatBase.saveBase()` и перерисовка сметы. Смета BazisReborn (`MatBase.build`) берёт из базы цену (если в прайсе нет своей цены строки), поставщика, ссылку, фото, остаток; лист ↔ м² по размеру листа.

### 4.2а. Окно «Поставщик» у строки сметы (`ui/sth_sup.js`, с 0.9.1, вариант «B»)
`Est.supEdit` заменён для плит, кромки, погонных, фурнитуры, профилей (если база материалов есть): сверху «Материал в базе» — «✓ название» (по связи `b.links` или найденный по наименованию/артикулу) и «Сопоставить…» (окно базы в режиме выбора); нет — «Нет в базе» и галочка «Записать в базу» с группой (список — все группы базы деревом, основные и подгруппы; `STH.groupOpts`, так же в окне «Нет в базе»). Ниже: ссылка, «Заполнить по ссылке» (`STHShop.read`: цена, артикул, поставщик, наличие, фото — картинкой через `/api/shop/image` под входом магазина, уменьшается; адрес фото — из разметки страницы, иначе оболочка сама находит на открытой странице самую большую картинку товара в верхней части, без логотипов и значков — `PICK_IMAGE_JS` в `main.js`, поле `image` ответа `/api/shop/fetch`), «Войти на сайт», цена, поставщик (из базы или новый), артикул, фото (файл, Ctrl+V). «Сохранить» пишет в материал базы (нет — создаёт с единицей, толщиной и форматом листа из проекта), связывает строку (`STH.linkSet`), убирает свою цену строки из прайса сметы — цена берётся из базы. Галочку сняли — как раньше (поставщик по названию, цена в прайс). Над сметой — «⟳ Обновить цены по ссылкам»: материалы строк этой сметы со ссылкой, по очереди с паузой 1,5 с, итог — окно «было → стало».

### 4.2б. «Заменить…» материалом из базы (`ui/sth_replace.js`, с 0.9.15)
В отличие от сопоставления, замена подменяет саму позицию: название, артикул, цена, поставщик, ссылка и фото берутся из выбранного материала базы и попадают в итоги, разделы, документы сметы, КП, счёт и заказ. Исходное имя модели остаётся в `name0` и в записи замены. Работает для плиты, кромки, погонных, профилей и фурнитуры; свои и расчётные строки комплектов не заменяются.
В окне после выбора товара: **«Количество модели»** — исходные количество и единица, цена базы пересчитывается в единицу строки, упаковка только справочно; **«По правилам базы»** — единица материала, пересчёт лист ↔ м² по формату, `MB.roundQty`, затем целые упаковки `packWhole`. Повторное «изменить» исходит из сохранённых `modelVal/modelUnit`, поэтому количество не пересчитывается дважды. Несовместимые единицы без формата листа показываются с предупреждением. Название, артикул, цена и количество заменённой строки только для чтения; «Считать / не считать» доступно.
Хранение: проект `we.sthReplace`, общая замена `b.sthReplace` (галочка «Запомнить для всех проектов»), ключ `вид|исходное имя в нижнем регистре`, значение `{mat, mode}`. Возврат без удаления общей замены пишет `we.sthNoReplace[ключ]=1`; с галочкой удаления общей — убирает правило из базы. Применение — `E.sthReplace` из обёртки `E.sthKits` до комплектов и итогов, без правки `core/estimate.js`. Оба прохода `MatBase.build` пропускают заменённые строки, чтобы прежнее сопоставление не вернуло старую цену/поставщика. `K.rowInfo` возвращает выбранный материал для упаковок и списания.

### 4.3. Ссылка на товар (`ui/sth_shop.js`)
Карточка материала → вкладка «Поставщик» → «Ссылка на товар»: **«Заполнить по ссылке»** (цена → «Цена в базовой валюте»; название, артикул, толщина, размер листа — только в пустые поля; «Нет в наличии»; остаток/актуальность/характеристики → примечание строкой `[сайт] …` (заменяется при повторе); поставщик — по названию сайта или домену, нет — заводится); **«Войти на сайт»**. Меню «Инструменты → Обновить цены по ссылкам…» — все материалы со ссылкой по очереди, пауза 1,5 с, сводка. Персональные цены МДМ-Комплект (4 098,90 вместо 6 558,24 «для физ. лиц») видны только после входа.

### 4.4. Заказы (`core/sth_order.js`, `ui/sth_orders.js`)
**Книга** — файл «STHGroup — заказы.json» в папке `settings.sthOrdersDir`, по умолчанию — папка базы материалов (общая), иначе папка данных. Формат `sthgroup-orders`: `{ next, clients[], orders[], cat }`. Перечитывается при возврате в окно, сохраняется через 0,4 с после правки.
**Папка заказа** (с 0.9.0): `<папка заказов>\Заказы\<номер клиент>` (`o.dir`, задаётся один раз, `O.dirName`). Файл модели копируется туда (`POST /api/sth/copy`; проект не одним файлом — и файлы рядом с тем же именем): при выгрузке из БАЗИСа (вкладка исходного файла меняется на копию; если копия новее файла выгрузки — открывается копия без перезаписи), при «+ Изделие», у старых заказов — при открытии. `items[].src` — исходный файл, по нему заказ находится при следующей выгрузке. **Щелчок по заказу** открывает его модели вкладками (раздел остаётся «Заказы»); в «Клиенты → Заказы клиента» щелчок по названию изделия открывает модель и раздел «Модель».
**Заказ** = несколько изделий (`items[]: {path, src, title, snap}`), `svc` (галочки/цены/кол-во услуг по ключам), `complex`, `ownMat`, `ownFit`, `markup`, `terms`, `payments[]`, `extra[]` (свои строки), `docs[]`, статусы: Расчёт, Согласован, В работе, Готов, Отгружен, Закрыт.
**Из выгрузки**: при открытии проекта `O.forProject` — по номеру из окна скрипта (`model.orderNo`), затем по файлу; нет — новый заказ (`<префикс>0001…` либо номер из окна), клиент по имени из окна (`model.customer`) — найти или завести. Тост «Заказ … создан».
**Сводка изделия** (`O.snapshot`): листы по материалам из раскроя (`P.summary`: std + rem) и вид работы каждого; деталей; мелкие детали (min(L,W) < порога): с кромкой (`shape.sides`) и с отверстиями (`st.holes.by[id]`); материалы и фурнитура — `R.groups['МАТЕРИАЛ']`, `R.groups['ФУРНИТУРА']` сметы (с базой). Открытое изделие — по текущему раскрою и смете; не открытое — по файлу (нет раскроя → быстрый раскрой quality 0).
**Расчёт** (`O.calc`), «как у фабрики» (образец — лист расчёта другой фабрики, КП-1167):
1. Обработка листового материала — **цена за лист по виду работы**. Вид работы: слова в названии материала + толщина «от/до» (`thMin/thMax`); первый подходящий, строка без условий — для остальных. Образец (с 0.9.0, по прайсу другой фабрики FOXY, цены заменить): ЛДСП 8–16 — 5500, ЛДСП 17–40 — 7500, шпон — 8500, МДФ 8–19 — 1500, МДФ 20–40 — 2500, ХДФ — 800, остальные «Распил, кромкооблицовка и присадка» — 5250. В книге до 0.9 (`cat.v2` нет) образцы добавляются к своим строкам, свой «Распил» для ХДФ (1050) остаётся.
2. Доп. обработка деталей — кромление и присадка мелких деталей (длина или ширина < 60 мм) по 420 ₽ за деталь.
3. Услуги к заказу — справочник с галочками; единица: за заказ, за лист (все листы заказа), за изделие, за деталь, % от суммы (безнал 7% — от услуг со скидкой + материалов). В заказе можно поправить цену и количество, «+ своя строка».
3а. Разделы-справочники `cat.groups` (с 0.9.0, образец FOXY): «Дополнительные работы» (за шт: еврозапил, интегрированная ручка, спил 45°, склейка, криволинейка…), «Фасады МДФ с эмалью» и «Фрезеровка без эмали» (за м²). В заказе — количество (`o.svc['g:<id>'].qty`), видны строки с количеством, остальные по «+ выбрать»; в КП и счёт идут только строки с количеством.
4. Скидка за комплекс — % от услуг (4%), галочкой в заказе. Срочный заказ (`o.urgent`, галочка справа): +30% к услугам со скидкой, срок в условиях — 3 раб. дня (`cat.urgentPct`, `urgentDays`, `urgentText`).
5. Материалы и фурнитура — по смете × (1 + наценка 15%), галочками «материал наш», «фурнитура наша».
Итог = услуги со скидкой + проценты + материалы; **аванс** = 70% услуг + 100% материалов (не больше итога); доплата; оплачено; долг.
**Условия «Важно знать»** — текст из справочника с подстановками `{аванс} {загрузка} {срок} {день} {хранение}`; в заказе — загрузка (низкая/средняя/высокая), срок (раб. дней), бесплатное хранение дней, ₽/сут.
**КП в PDF** (макет «B», выбран автором): шапка с логотипом и оранжевой полосой, блоки таблицами, справа карточка «Итого / скидка / материалы / аванс / доплата», «Материалы в заказе», «Важно знать». **Счёт в PDF**: реквизиты компании (справочник → «Компания»), позиции, скидка, итого, оплачено, к оплате, аванс.
**Прайс для клиента** (с 0.9.8, вариант «2» — карточки в две колонки, как у FOXY; кнопка в «Заказах» справа): `O.priceList(b, {pct, hide, date, noTerms})` — разделы «Работа за лист», «Услуги» (без строк «% от суммы» — они в условиях), разделы доп. работ и фасадов; название «ЛДСП 8–16 мм: распил, кромка» без примечания делится на название и примечание; надбавка/скидка в % (округление до рубля); «Условия» — срок, срочно, скидка за комплекс, наценка, аванс, безнал. Окно: дата «цены действуют с», %, галочки разделов и строк, «Условия внизу» — запоминается в `cat.pl`. Предпросмотр → PDF. У строк справочника — поле «Примечание для прайса» (`note`).
**Справочник и цены…**: Работа за лист (с толщиной от/до), Мелкие детали, Услуги, Доп. работы и фасады (разделы и строки), Скидка/наценка/аванс/префикс/следующий номер, Условия, Компания, Папка заказов.

### 4.5. Рабочее пространство, CRM и оформление 2.0
- **«Сегодня»** считает сводку по той же книге заказов (`STHWorkspace.summary`), не требует открытого проекта. Центр уведомлений собирает сообщения программы; строка состояния показывает проект, текущий раздел и CRM; плавающий индикатор показывает ход долгих операций. Плотность интерфейса выбирается в настройках.
- **CRM** по умолчанию настроена на `https://crm.migman.ru/app/`. Адрес преобразуется в API источника: вход `POST /api/login` с `{email, password}`, затем `GET /api/data/requests` и `GET /api/data/clients` с cookie-сессией. Пароль и cookie не передаются в окно и записываются только после шифрования Electron `safeStorage`; открытого запасного хранения нет. Внешний ID заказа — `crm:<id>`, повторный приём не создаёт дубли.
- Этапы CRM: `new_request` → `calc`, `contract_agreement`/`procurement` → `agreed`, `production` → `work`, `assembly_feedback` → `ready`, `completed` → `closed`. При автопроверке новые заявки создают карточки и показываются в окне новых заказов; доступны ручная синхронизация и проверка соединения.
- **Резервные копии** создаются каждые 30 минут из открытой базы материалов. Файл копируется в `.sth-backups` рядом с базой с датой в имени, основной файл не заменяется; старые копии удаляются после 12 последних.
- **Темы** добавляются в штатный `BM.THEMES`: «Светлая мастерская» (светлая), «Северный синий» (светлая), «Графит» (тёмная). Выбор сохраняется в `settings.theme`, применяется через `App.applyTheme` и восстанавливается после перезапуска.

**База материалов** (`bazisreborn-matbase`, файл выбирается в окне базы):
- `links {"<вид>|<имя в нижнем регистре>": id материала}` — «Сопоставить с базой».
- `sthReplace {"<вид>|<исходное имя>": {mat, mode}}` — общие замены позиций сметы (`mode`: `model` — количество модели, `base` — по правилам базы).

**Проект .bmk** (`work.est`): `sthSplit {"<имя>": {name, parts}}`, `sthKits[]`, `sthNoKit {ключ: 1}` — комплекты этого проекта; `sthReplace {ключ: {mat, mode}}` — замены позиций этого проекта, `sthNoReplace {ключ: 1}` — не применять здесь общую замену; `rows[]` — свои строки (порядок перетаскиванием).

Скрипты проверок окна в репозитории не лежат (Python + Playwright писались по ходу работы). Окна, которые ждут ответа (`U.modal`), из Playwright вызывать через `setTimeout(() => …)`, иначе `evaluate` ждёт закрытия окна.

## 7. Сборка и выпуск

**Выпуск = поднять `version` в `package.json` и `git push` в `main`.** GitHub Actions (`.github/workflows/build.yml`, windows-latest, Node 20): `npm install` → `npm run test:ci` → `electron-builder --win nsis --publish always` (токен `GITHUB_TOKEN`) → выпуск `v<версия>` с `STHGroup-Cutting-Setup-<версия>.exe`, `.blockmap`, `latest.yml`. Установленные программы при запуске видят новую версию и обновляются. Отправка тега напрямую заблокирована — только через push в main.
Установщик NSIS: на пользователя, можно выбрать папку, ярлыки «STHGroup», русский язык, значок `assets/icon.ico`. `build.files`: main.js, server.js, sth_backup.js, sth_crm.js, web/**, bazis/**, assets/**, package.json.
Локальная сборка: `npm run dist` (на Windows).

## 9. Решения автора (не менять без его согласия)

- Программа — копия BazisReborn по окну и работе; **Electron**, обновления как раньше; **репозиторий открытый** (автор знает, что код окна BazisReborn в нём виден всем).
- Разделы: Модель, Раскрой, Смета, База, Заказы, Клиенты. **Нет**: Деталировка, Присадка, Сборка, Отзывы, регистрация, счётчик установок, Android, «по ссылке на Яндекс Диск».
- Модель попадает в программу **только через скрипт выгрузки STHGroup** (.b3d напрямую больше не открывается).
- Тема — **только STHGroup, вариант C** (мягкий графит + оранжевый, оранжевая линия под шапкой). Заставка при запуске — **вариант «Спокойная»** (знак со свечением, буквы названия по очереди; выбран автором 03.11.2026 из трёх вариантов вживую).
- Окно скрипта — **вариант C**. Раздел «Заказы» — **вариант A**. КП — с 0.9.6 **вариант «2»** (шапка как у счёта, итог карточкой справа); счёт — **вариант «A»** (два блока «Исполнитель | Заказчик», полоса заказа, сумма прописью); прайс для клиента — **вариант «2»** (карточки в две колонки). Картинки выбранных вариантов — `docs/design/`.
- Окно «Поставщик» у строки сметы — **вариант «B»** (блок «Материал в базе»), всё пишется в базу материалов; обновление цен с сайтов — кнопками («Заполнить по ссылке», «Обновить цены по ссылкам» над сметой и в базе).
- Смета: **без работ** (распил, кромкование, пазы, упаковка, отверстия — в заказе), без галочек «Считать разделы», без «Как на бумаге» — документ смотрится в предпросмотре.
- Структура базы — **схема `docs/design/Структура_базы.png`**: разделы по виду, ≤ 4 уровней, фурнитура по виду, поставщик — в карточке, МДФ и ХДФ раздельно, признаки кромки — классами; «Примечание» разбирается в поля.
- Комплекты: «Разделить…» / «Объединить в комплект…» правой кнопкой, «Запомнить для всех проектов» — галочкой (по умолчанию включена). Упаковка: цена за упаковку → за штуку, «целыми упаковками» — галочкой.
- Модель изделия хранится копией в папке заказа «Заказы\<номер клиент>»; щелчок по заказу открывает модели.
- Заказ = несколько изделий; книга — в общей папке; работа в КП — за лист пакетом по виду работы; номер — автоматически STH-0001…, если вписан в окне скрипта — он; заказ из выгрузки создаётся/дополняется сам; «Клиенты» — отдельной кнопкой.
- «Нет в базе» — список с галочками и выбором группы. Мелкая деталь — **длина или ширина** меньше порога. Аванс — % услуг + % материалов. Скидка за комплекс — галочкой в заказе. Условия: загрузка, срок, хранение и погрузка + общий текст в справочнике.
- В смете — кнопка «Сопоставить с базой материалов» **напротив каждого товара**; смета должна быть полностью сопоставима с базой.
- База материалов — полная копия базы BazisReborn + ссылка на товар с автозаполнением, как было в STH.
- Правильность расчёта сверять со сметой и раскроем BazisReborn на той же модели.

## 12. С чего начать новой нейросети

1. Прочитать `AGENTS.md` (правила работы с автором) и этот файл.
2. `git clone https://github.com/MatrixMind2026/sthgroup-cutting && cd sthgroup-cutting && npm install && npm test`.
3. Окно без Electron: `node server.js /tmp/sth-data /путь/к/проекту.bmk 47800` → адрес из первой строки вывода открыть в Chromium. Образцы проектов делает `node test/fixtures.js` (в `test/out/`, например `est.bmk`).
4. Своё STHGroup — в отдельных файлах: `web/ui/sth.js` (скрипт, «Нет в базе», «Сопоставить», смета без работ), `sth_orders.js` + `core/sth_order.js` (заказы, клиенты, справочник, КП, счёт, прайс), `sth_sup.js` (окно «Поставщик»), `sth_kits.js` (комплекты, упаковка в смете), `sth_replace.js` (замена позиций сметы материалами базы), `sth_drag.js` (перетаскивание), `sth_mb.js` (групповое редактирование, Ctrl+A, выбор материала для сметы — в окне базы), `sth_shop.js` + `core/linkparse.js` (сайты магазинов), `sth_restruct_ui.js` + `core/sth_restruct.js` (перестройка базы), `ui/sth_splash.js` (заставка). Правки в файлах BazisReborn помечены комментарием `STHGroup` — `grep -rn STHGroup web/`.
5. Выпуск — поднять `version` в `package.json`, `npm test`, `git push` в `main`; в каждом выпуске дописать строку в раздел 8 и, если поменялось поведение, — нужный раздел здесь.
6. Личные файлы автора (базы .dbf/.FDB, модели, скрипт «СМЕТА») в репозиторий не класть.
